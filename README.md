# Meritocracy MVP

2–6 人、12 轮、秘密行动 + 全局事件的局域网网页游戏。纯数字版本，逻辑完整可测试。
金钱隐藏、政绩公开，爬到国家主席即胜。

## 运行

```bash
python3 -m pip install -r requirements.txt   # fastapi / uvicorn / websockets
python3 server.py                            # 默认 0.0.0.0:8000
python3 server.py --port 9000
```

启动后终端会打印局域网地址。打开网页之后：

1. 输名字 → **创建房间**，拿到一个 4 位房间号
2. 大厅里点 **「+ 添加一名 AI 玩家」** 补人（想加几个加几个，上限 6 人）
3. 别人在同一个 WiFi 下打开网页，输入房间号就能进来
4. 房主点开始

AI 玩家由服务器上的 `ai.py` 驱动，走的是和真人**完全一样**的接口——
只吃 `public_state()` 和它自己的 `private_state()`，看不到你的钱和手牌。

```bash
python3 -m unittest discover -s tests -t .              # 单元测试（317 个）
python3 simulator.py --players 6 --games 10000          # 模拟器
python3 analysis.py --section full --games 2500 --agents smart   # 完整平衡报告
python3 analysis.py --section triangle               # 鹬蚌相争的目标动态成不成立
python3 analysis.py --section ablation               # 每张牌的因果价值（带置信区间）
python3 analysis.py --section funnel                 # 金钱/政绩两条路线的端到端漏斗
```

> 目录本应放在 `/meritocracy`。macOS 的系统完整性保护不允许在根目录下新建目录，
> 所以这套代码放在 `<repo>/meritocracy`。放进容器或 Linux 机器时把整个目录拷到
> `/meritocracy` 即可，代码里没有任何硬编码的绝对路径（数据库默认写在脚本同目录，
> 可用环境变量 `MERITOCRACY_DB` 覆盖）。

## 结构

```
meritocracy/
    server.py        FastAPI + WebSocket，只做收发、计时、持久化
    game.py          对局状态机（服务器权威），不依赖 Web
    rules.py         全部规则计算，纯函数
    models.py        数据模型（枚举 / 玩家状态 / 结算产物）
    config.py        所有平衡参数，逻辑代码里没有魔法数字
    storage.py       SQLite 持久化，重启可恢复进行中的对局
    simulator.py     无界面模拟器，与 Web 共用 game.py / rules.py
    ai.py            思考型 AI：只吃公开 payload，推断对手隐藏的金钱
    analysis.py      平衡性分析：领先易手、官职转移、行动价值、三角动态、消融、漏斗
    static/          index.html / app.js / style.css
    tests/           单元测试 + 端到端 WebSocket 测试 + 前端渲染冒烟测试
```

依赖方向是单向的：`config → models → rules → game → {server, storage, simulator, analysis, ai}`。
`rules.py` 和 `game.py` 不 import 任何 Web 代码，所以模拟器可以直接驱动同一套逻辑。

## 私密数据

服务器对每个连接发送两段数据：

* `public` —— 所有人一致：轮次、阶段、每位玩家的 `name / rank / merit / tenure`、
  当前事件（仅在锁定之后）、公开通报、财富广播。
* `private` —— 只发给本人：`money / hand / selected_action / selected_target /
  private_result`。

公开 payload 里从来不包含别人的金钱、手牌、行动、目标，也**不包含举报者的身份**。

**政治攻击是例外：它是明枪，公报里点名写着谁抢了谁的功劳**
（`ATTACK_ANNOUNCES_ATTACKER`，`player_facts.attacked_by`），
这样被抢的人才知道该报复谁。匿名举报仍是暗箭，举报者身份永远不进任何 payload。

`test_game.py::TestPrivacy` 用**白名单**卡住公开字段的集合，
`test_server_e2e.py` 在真实 WebSocket 上再验一遍。
加任何公开字段都会被这道白名单拦下来，必须显式确认后才放行。

事件在所有人锁定之后才由服务器抽取，`ACTION_SELECTION` 阶段的 `current_event` 恒为 `null`。

## 收益计算

统一顺序：`卡牌基础数值 → 事件修改 → 官职倍率 → 向下取整`。

倍率全部用 `fractions.Fraction`，中间不出现浮点数，只在最终收益处 `floor` 一次，
所以 `9 × 0.5 × 1.5 = 6.75 → 6` 这种情况不会有误差。

## 一轮出两张牌 + 晋升卡

* 每轮发 `HAND_SIZE`（6）张，从中选 `PICKS_PER_ROUND`（2）张打出去
* 牌是从一副**真牌库**里不放回地发，所以 `CARD_DEAL_DISTRIBUTION` 里写几张就最多几张
  （以前是按权重有放回抽样，26.7% 的手牌会出现 3 张以上同名牌，和配置看着的意思对不上）
* 晋升**必须打出晋升卡**（`PROMOTION_REQUIRES_CARD`）：政绩升职 / 贿赂升职 / 通用升职
* 工龄晋升是唯一例外，仍然自动：连续 `TENURE_REQUIRED` 轮没晋升就升一级，
  这是抽不到晋升卡时的兜底
* 一轮最多升一级；多张晋升卡只有一张生效，政绩优先于金钱
* **工资在回合开始时就发**（`rules.pay_salaries`，跟着发牌一起），不是等结算。
  这样本轮工资当轮就能用——基层的一轮工资正好够换一次牌
* **换牌要花钱**（`REDRAW_COSTS` 底价按当前官职定，`REDRAW_COST_GROWTH` 控制同一轮内的涨幅）：
  * 底价 `[1, 3, 6, 12]`，**同一轮里每换一次翻一倍**：1 → 2 → 4 → 8
  * 前期好换、后期难换，两个口径同时成立：
    对每轮工资是 1.0 / 1.5 / 1.5 / 2.0 轮，对升职门槛是 7% / 14% / 20% / 32%
  * 基层一轮工资正好换一次（手气差不至于毫无办法），省级一次要攒两轮
  * 翻倍那条是防"有钱人在一轮里反复重抽直到摸出想要的牌"
  换掉了原来"每升一级白送一次"：那个机制和钱无关，攒着不用毫无损失，
  而且 AI 从来不用，等于只给真人加了一层优势
* **政治攻击 = 抢功 + 暂缓升职**（`ATTACK_MODE="steal_work"`）：
  * 没收目标本轮产出的 `ATTACK_STEAL_FRACTION`（1/2），所有抢功的人平分这一份，
    目标保留另一半 —— 是**转移**不是破坏
  * 目标本轮没生产（比如正忙着干扰别人）→ **一点都抢不到**，
    改成按他的官职扣一笔政绩（`ATTACK_MERIT_PENALTY` 走目标官职的 WORK 倍率：
    基层 4 / 县级 6 / 市级 8 / 省级 10）。这笔是**罚款不是赃物**，攻击者拿不到，
    所以互相攻击仍然两败俱伤，渔翁得利那条不受影响
  * 判据是"这轮有没有干正事"= **埋头工作** 或 **凭政绩升职**。
    闷声捞钱、拿钱买官、忙着搞别人都算没干，照罚。
    凭政绩升职的人已经被这一刀暂缓了，再罚就等于把"拦晋升清零政绩"偷偷加回来
  * 同时让目标这一轮**政绩升职暂缓**（`ATTACK_WIPES_MERIT_ON_BLOCK=False`，政绩不掉）
  * **公开署名**（`ATTACK_ANNOUNCES_ATTACKER`），被抢的人知道该报复谁；举报仍匿名
  * 这两条造出了「鹬蚌相争，渔翁得利」：
    打生产者能反超他，互相打则两人都没产出、埋头建设的第三人得利。
    用 `analysis.py --section triangle` 直接验这两条
* **升职的克制矩阵**：

  | 升职方式 | 被政治攻击 | 被举报查实 |
  |---|---|---|
  | 政绩升职 | 暂缓，政绩保留 | 不受影响 |
  | 贿赂升职 | 不受影响 | 失败，金钱损失 |
  | 通用升职 | 改走贿赂 | 走政绩，不受影响 |
  | 通用升职 + 两样都挨 | 失败，金钱损失，政绩保留 | |

  攻击克政绩路线，举报克金钱路线。
  **省级→主席这一步也适用同一张表**：虽然钱和政绩要一起花，但"走正规程序还是走关系"
  由你打哪张卡声明 —— 打政绩升职只怕攻击（被拦下只是暂缓，一分钱不损失），
  打贿赂升职只怕举报（赔钱记警告）。通用升职 = 先当政绩升职算，被拦下再回退成贿赂升职
* **举报查实的后果是"降职警告"制**，不再是一次被抓就打回基层：
  * 判定：本轮**贪了钱**，或者**拿钱买官**（`REPORT_CATCHES_BRIBERY`，默认开）
    * 开着 = 金钱路线赚和花两头各过一道 ~31% 的关
    * 关掉 = 举报只管贪污，但查实后这一轮的贿赂升职照样作废、钱也要不回来
    * **重做过 A/B，结论是保持开着** —— 见下面"两次测量翻车记"
  * 本轮贪污所得全部没收（存款不动，不再有"抄家"）
  * 拿钱买的官作废，而且**行贿的钱要不回来**
  * 记一次降职警告 + 工龄清零；攒满 `WARNINGS_BEFORE_DEMOTION`（2）次才降一级、警告清空
  * `MAJOR_CORRUPTION_WARNINGS` 默认 1 = 大案不再有额外后果；设成 2 可恢复"一次大案当场降级"
  * 好处是惩罚从断崖变成可以计入预算的分期账单，贪污终于敢用
* **举报人只拿没收额的 `REPORT_REWARD_RATIO`（默认 1/2），其余充公**
* 平衡工具：
  * `analysis.py --section triangle` —— 目标动态（鹬蚌相争）是否成立
  * `analysis.py --section ablation` —— 每张牌的因果价值，**默认只禁 1 席**
  * `analysis.py --section ablation --sweep` —— 禁 1~5 席的整条曲线
  * `analysis.py --section funnel` —— 金钱/政绩两条路线的端到端漏斗
  * `analysis.py --set KEY=VALUE` —— 临时改一条规则再跑，任何规则 A/B 都是一条命令

### ⚠️ 两次测量翻车记

平衡工具错了比游戏错了更糟 —— 它会让你信心十足地把规则改坏。这里记两次。

#### 坑一：禁半桌会给"人多才安全"的牌定错价

**贪污是一张「法不责众」的牌** —— 同一轮一起贪的人越多，每个人越安全
（查实率 1 人 36.9% → 6 人 14.3%）。原因是举报牌的供给是固定的（牌库里 2/19），
一个人贪就吃下全部怀疑，六个人贪就摊薄成六份。

所以**禁用几席会直接改变结论**。同一张贪污牌：

| 禁用席位 | 1（均衡点） | 2 | 3 | 5 |
|---|---|---|---|---|
| 贪污 | −0.80 | +1.57 | +3.05 | +6.97 |

老的消融测试禁半桌（3 席），于是一直报告"贪污偏弱、不如不用"——**那是测量假象**。
现在默认只禁 1 席（别人都照常玩、只有我少一个选项），并且**打印 95% 置信区间**：
3000 局时区间半宽约 ±1.45，小于这个数的差值一律当"分不出来"。
用 `--sweep` 能一眼看出一张牌是不是"人多才安全"（曲线单调上升）。

#### 坑二：胜率太钝，规则 A/B 要用漏斗

用修好的消融重测 `REPORT_CATCHES_BRIBERY`，三张牌在两种配置下**大多都跨 0**，
光看胜率根本分不出该开还是该关。换成漏斗（按事件计数，2.6 万个样本）立刻清楚：

| 端到端存活率 | 金钱路线 | 政绩路线 | |
|---|---|---|---|
| 开着（现状） | 49.4% | 52.0% | 两条路基本对称 |
| 关掉 | **56.9%** | 50.9% | 金钱反超 6 点，矫枉过正 |

消融也印证：关掉之后贪污变成 **−7.50 [−8.75, −6.25]**（区间整体在 0 以下 = 确定超模）。
**所以老结论"应该关掉"是反的**，保持开着。

教训：胜率是"一局一个样本"，规则改动的效应常常淹在噪声里；
漏斗是"一个事件一个样本"，同样的机器时间能得到几十倍的精度。
规则 A/B 先看漏斗，胜率只作旁证。
* **升完一级，剩下的政绩一律 ÷`MERIT_OVERFLOW_DIVISOR`，不管是怎么升上去的**
  （`PROMOTION_ALWAYS_DECAYS_MERIT`）：贿赂上位、熬工龄上位都一样。
  否则"攒政绩 + 花钱升职"能把政绩原封不动带过一级，等于白拿一级，
  贿赂升职会严格优于政绩升职。金钱没花掉就原样留着
* 同名牌能出两张（手里有两张的话），`WORK + WORK` 是明确的"全力生产"选择
* **出牌顺序由玩家自己排，结算严格照着走**——顺序本身就是一个决策：
  * 「政绩升职 → WORK」：先升官，这轮的活按**新官职**倍率算，也不吃晋升的 /5
  * 「WORK → 政绩升职」：先干活，产出按**旧官职**算，多出来的还要被 /5 砍
  * 门槛还没够的时候把晋升卡排前面 = 白打，服务端不会替你重排
  * 被政治攻击时政绩**不掉**，只是这一轮升不上去；手里是"通用升职"的话还能改走金钱
  * 排在举报/攻击**后面**的晋升卡会等到赃款到账后再结算——
    想用刚抄来的钱升官，就得把晋升卡排在举报后面
  * **被举报查实只堵金钱那条路**：贿赂升职作废且钱要不回来，
    政绩升职不受影响（拦政绩是政治攻击的活）。被诬告的清白玩家完全不受影响
  * **这一轮刚贪来的钱当轮花不出去**：排在贪污牌后面的晋升卡要等举报结算完才兑现。
    少了这条，"贪一笔立刻洗成官职"就能躲开没收——举报人查实了分不到钱，
    被举报的人升一级又降一级、官职净变化为零，举报等于白打
* 整轮的大框架：工资 → 锁定干扰目标 → **各人按自选顺序出牌** → 攻击效果
  → 举报判定 → 没收/降级 → 补结算延后的晋升卡 → 工龄

为什么这么改：一轮只出一张时，干扰行动要占掉 **100%** 的产出，在固定门槛的赛跑里
怎么调数值都不划算（这一点实测反复验证过）。出两张之后机会成本降到 **50%**，
干扰终于成立。副作用是"政绩没涨 ⇒ 他本轮没干活"这个推理失效了，隐藏信息层更厚。

代价是干扰牌一下子变得太好用（出现过"全场互相攻击、没人建设"的退化局面），
所以牌库里干扰牌的占比要压到 12% 左右——见 `CARD_DEAL_DISTRIBUTION` 的注释。

## 终局复盘（最后一名为什么输）

游戏结束时，每个玩家的 **private state** 里会多出一份 `postmortem`：
名次、晋升次数与他人平均的对比、以及"比别人吃亏最多的三件事"
（政绩被抢 / 赃款被没收 / 资历被搅黄 / 举报扑空 / 攻击扑空 / 晋升卡没用上 / 回合花在干扰上）。

里面含金钱数字，所以**只发给本人**，绝不进公开状态（`TestPostmortem` 有用例守着）。

批量版本在 `analysis.py --section postmortem`：跑 N 局，把每局最后一名的败因
归口到「被针对 / 运气 / 自己选的」三类，并打印若干局的具体分析。

## 举报的完整结算

举报查实（目标本轮**贪了钱**，或者**拿钱买官**）之后依次发生：

1. **没收赃款** —— 只没收本轮那一笔，**存款不动**（警告制下不再有"抄家"）。
2. **行贿的钱打水漂** —— 拿钱买的官作废，钱也要不回来；这笔钱同样并进赃款池。
3. **分赃** —— 赃款里只有 `REPORT_REWARD_RATIO`（1/2）归举报人，其余充公；
   多人举报再平分，向下取整，零头也充公。
   事件（反腐风暴）产生的那一份举报没有举报人，全额充公。
4. **记一次降职警告 + 工龄清零** —— 攒满 `WARNINGS_BEFORE_DEMOTION`（2）次
   才降一级，然后警告清空重新记。

分赃在延后的晋升结算之前完成，所以**把晋升卡排在举报后面就能用刚抄来的钱升官**
（排在前面则花不到——那笔钱还没到账）。
分到的钱不算"贪污"：不进财富广播，也不会让举报人自己变成可被查实的对象。

互相举报（甲举报乙、乙同时举报甲）时，所有没收金额先一次性算完再统一扣除和发放，
不会因为结算先后顺序让某一方多拿或少拿。

公报会区分**真人举报**和**反腐风暴**：后果一样，但不说清楚的话，被风暴扫到的人
会以为桌上有人在针对自己，然后去报复一个根本不存在的敌人。

## 政治攻击：抢功（对规则书第 12 节的改动）

规则书原版的 ATTACK 是「目标本轮没打 WORK 就扣 1 点政绩，打了 WORK 则免疫」。
实测它在任何数值下都不划算——因为它**纯利他**：我付出一整个回合，
好处被其余所有对手平分（`ai.py:_diffusion()` 里写着 `1/(N-1)`，6 人桌打 2 折）。

默认改成 `ATTACK_MODE = "steal_work"`，把**破坏变成转移**：

| 目标本轮的情况 | 挨攻击的后果 |
| --- | --- |
| 在埋头工作（产出了政绩） | 产出的 **1/2 被抢走归攻击者**，所有抢他的人平分这一份，他保留另一半 |
| 打了政绩升职且够门槛 | **暂缓升职**——这轮升不上去，但**政绩一点不掉** |
| 没干正事（捞钱 / 买官 / 搞别人） | 政绩 −`ATTACK_MERIT_PENALTY` 走目标官职倍率（基层 4 / 县级 6 / 市级 8 / 省级 10）。这是**罚款不是赃物**，攻击者拿不到 |
| 工龄 | **不动** |

关键是那条"**打本轮没生产的人就抢不到东西**"——整个「鹬蚌相争，渔翁得利」
都是从这一条长出来的：打生产者能反超他，互相打则两人都没产出、
埋头建设的第三人得利。`analysis.py --section triangle` 直接验这两条。

**抢上位者天然更值**：抢到的是目标那一级的绝对产出，
省级一张 WORK 产 15 点，基层只产 6 点。

三种历史方案都完整保留并各有测试（钉在各自的夹具配置上）：
`merit_penalty`（规则书原版）、`denial`（纯破坏）、
`steal_merit`（按存量抢）、`negative_sum`（负和）。

## 以权谋私（GRAFT）—— 一张特殊的贪污卡

不是独立门类，就是**贪污卡的一个变种**：钱比纯贪污少（期望 10 vs 18），
但同一张牌顺带带政绩（`GRAFT_MERIT_RATIO` = 1/4，基层期望 2.1）。
赚到的钱**照样算本轮贪污额**，一样会被举报查实。

**那点政绩是严格少于埋头工作的**，每一级都不许重叠
（基层 2~3 对 4~8，省级 5~7 对 10~20）。
比例原来是 1/2，两段是 4~6 对 4~8 ——一张好的以权谋私能压过一张差的埋头工作，
而且还白送 10 块钱，捞钱的顺手之作不该比老实干活还长脸。
`TestCardDistributions` 里有用例逐级守着这条不重叠。

## AI 的干扰权重是校准出来的，不是拍的

`ai.Weights.interfere_attack / interfere_report` 默认 **0.2**，来自一次校准：
把权重从 1.0 往下扫，直到"禁用这张牌的 AI"不再打得更好（消融差归零）。

1.0 时 AI 会把干扰高估约 **5 倍**——攻击出牌率虚高到 114%，但消融显示
不用攻击的 AI 反而多赢 4.87 个点。**所以出牌率反映的是 AI 的偏好，不是牌的强度；
判断一张牌强不强要看消融，不能看出牌率。** 这个坑踩过一次，写在这里免得再踩。

另一个 AI 的坑：目标打分打平时要**随机挑**，而且容差必须是**相对**的。
早先用的是绝对容差 0.02，开局够用；到了中局各目标的攻击分普遍只有 0.006~0.016，
整个区间比容差还小，于是"谁快升职了"这套威胁模型算完就被扔掉、变成纯随机挑人。

## 平衡数值的联动关系（改一个必须连带改另一个）

这几项互相咬得很死，实测踩过的坑：

| 改动 | 必须连带调整的 |
| --- | --- |
| WORK 牌面期望（现 6） | 政绩门槛要同比例动，否则政绩路线平白变慢 |
| CORRUPT 期望（现 18 = WORK 的 3 倍） | 金钱门槛同比例动，同理 |
| `GRAFT_MERIT_RATIO` | 调高会让以权谋私的政绩段和埋头工作重叠，见上面那一节 |
| `ATTACK_STEAL_FRACTION` | 直接决定三角动态成不成立，改完必须重跑 `--section triangle` |
| `TENURE_REQUIRED` 3 → 4 | **这一项是悬崖**：12 轮 ÷ 3 = 正好 4 级，纯熬资历就能当主席（主席率 100%）；改成 4 之后只能熬到省级，必须至少靠资源升一次，门槛不跟着降就会变成"12 轮打满没人登顶"（主席率 13%）。最终门槛整体 ×0.65，落在主席率 66% |
| `PICKS_PER_ROUND` 1 → 2 | 干扰行动的机会成本减半，干扰牌在牌库里的占比要压下来，否则会出现"全场互攻、没人建设" |

当前落点（6 人满桌思考型 AI）：平均 8.6 / 12 轮，主席率 96.8%，
并列冠军 0.11%，领先者每局易手 5.0 次，全程独占领先到夺冠 5.0%。

省级→主席那一步曾经是堰塞湖（升职率 8.95%，其他三级 41%+），
原因是当时三张晋升卡在那一级一视同仁、攻击和举报都拦得住。
改成"由卡声明走哪条路"之后升到 13.15% —— 仍然是最难的一步，但不再卡死。

## 规则书里没写死、需要实现方决定的地方

这些决定全部集中在 `config.py`，附了开关，调平衡时可以直接翻转：

| 情况 | 本实现的选择 | 开关 |
| --- | --- | --- |
| 举报人拿走多少 | 没收额的 1/2，其余充公；只没收本轮那一笔，存款不动 | `REPORT_REWARD_RATIO` |
| 多人举报同一个人怎么分赃 | 平分，向下取整，零头充公 | `REPORT_REWARD_SPLIT_EVENLY` |
| 举报查实后同一轮还能不能晋升 | 花钱那条路不能（政绩升职不受举报影响） | `DEMOTED_CANNOT_PROMOTE_SAME_ROUND` |
| 多人举报同一个人是否叠加降级 | 不叠加（"中央反腐大筛查"会给所有人加一次举报，叠加惩罚过重） | `MULTIPLE_REPORTS_STACK` |
| 第 16 节"金钱按晋升成本扣除" | 不再额外扣——钱已经被举报人拿走了，第 16 节只保留"晋升失败"的结论 | — |
| 多人攻击同一个人 | 伤害只结算一次，收益由攻击者平分（原版模式下政绩处罚按人次叠加） | — |
| 降级当轮结束时的工龄 | 保持 0（第 14 节明确写了 `tenure = 0`），不再 `+1` | — |
| 一轮最多晋升几级 | 一级。工龄晋升与资源晋升不叠加 | — |
| 工龄能否直接升到国家主席 | **不可以**，最高熬到省级；主席必须靠资源升 | `TENURE_CAN_REACH_PRESIDENT` |
| 省级 → 主席的门槛 | 金钱和政绩**同时**达标；但怕攻击还是怕举报，由你打哪张晋升卡决定 | `PROMOTION_REQUIRES_BOTH` |
| 升职后剩下的政绩 | 一律 ÷5，**不管是怎么升上去的**（贿赂升、熬工龄也一样） | `PROMOTION_ALWAYS_DECAYS_MERIT` |
| 同一轮多人登上国家主席 | 按"金钱 > 政绩"决胜。配合双条件门槛，真平局已降到 0.08% | `PRESIDENT_TIEBREAK` |
| 终局排序口径 | 金钱 > 官职 > 政绩（`FINAL_RANKING_KEYS`），已判定的赢家排最前 | `FINAL_RANKING_KEYS` |

平衡实验用的额外杠杆（默认值等同规则书，改了才会变）：

| 杠杆 | 作用 |
| --- | --- |
| `CARD_DEAL_DISTRIBUTION` | 发牌权重。把 `"ATTACK"` 那一项删掉就是"完全取消政治攻击"的三张牌版本 |
| `ATTACK_SPARES_WORKERS` | 规则书 §12 的"WORK 玩家免疫政绩处罚"。**仅 `merit_penalty` 模式生效** |
| `REPORT_CATCHES_BRIBERY` | 拿钱买官算不算可举报的罪名。重做过 A/B，保持开着（见"两次测量翻车记"）|
| `MAJOR_CORRUPTION_WARNINGS` | 大案记几次警告。默认 1 = 大案不再有额外后果；设 2 恢复"一次大案当场降级" |
| `WORK_RANK_MULTIPLIERS` / `MONEY_RANK_MULTIPLIERS` | 把 WORK 和 CORRUPT 的官职倍率拆开。例如 WORK 固定 x1，逼高位玩家必须捞钱 |

规则书第 16 节（两种门槛都够 + 被 ATTACK + 被 REPORT ⇒ 晋升失败）现在是
上面那张克制矩阵的一个格子：攻击堵死政绩那条路、举报堵死金钱那条路，
两样都挨就升不上去（钱损失、政绩保留）。代码里仍然单独打标记
（`promotion_blocked_by_attack_report`），只为了播报和统计。

另外为了让游戏不至于每轮都天下大乱，事件表里加了一个空效果的「风平浪静」
（规则书要求的 5 个事件全部实现，这是第 6 个）。权重都在 `EVENT_DEFINITIONS` 里。

事件卡调过四处（都是实测出来的）：

* **重点项目 +1 → +4**。+1 时全桌 6 人总共只多出 8 点政绩、人均 1.3 点，
  而门槛是 15~66，存在感评分 0.16、领先易手只比基准高 1.0% —— 完全是噪音。
  改成 +4 之后存在感 0.57、领先易手 +3.5%。
* **风平浪静权重 30 → 12**。原来近三成的轮次揭牌是"什么也没发生"，
  揭事件这个环节大部分时候没有反馈。
* **中央反腐大筛查 → 反腐风暴**。原来是"所有人各记一次举报"，存在感评分最高（3.71）
  却完全不造成反转（领先易手 −0.5%）——因为它**均匀**打击所有贪污者，不改变相对排序。
  改成只查办本轮贪污额排前 1/3 的人（`EVENT_STORM_FRACTION`，向上取整，
  并列卡在分界线上的一起算）。
* **政治环境稳定下架**（权重设 0，定义保留着方便恢复）。它是全场唯一显著**降低**
  反转率的事件（领先易手 −6.2%），而且只保护走政绩路线的领先者：那一轮谁也拦不住
  他兑现晋升，走金钱路线的人却照样怕举报。属于无条件的反追赶机制。

`analysis.py --section events` 会算每张事件卡的"存在感"（各指标相对空事件的变化幅度）
和"能不能造成反转"（该事件那一轮领先者易手的比例）。

## 状态机

```
LOBBY → ACTION_SELECTION → REVEAL_EVENT → RESOLUTION → ROUND_RESULT → …
                                                               ↓
                                                           GAME_OVER
```

有人达到国家主席、或第 `MAX_ROUNDS`（12）轮结算完毕时，直接进入 `GAME_OVER`
（结束画面里同时显示最后一轮的结算，所以不会漏看）。

**每个玩家自己排两张牌的先后，结算严格照着走**——先升职还是先干活是个真决策：
先升职则本轮产出吃新官职的倍率、也不被晋升的 ÷5 砍；先干活则反过来。
门槛还没够就把晋升卡排前面 = 白打，服务端不会替你重排。

客户端只能提交 `join / select / lock / ready / redraw`
（外加房主的 `start / force / add_ai / remove_ai / reset`）。
房主随时可以 `reset` 结束当前这局重开，**原班人马留在房间里**
（编号、名字、token、AI 身份都不变），分数和历史清零。
所有随机数由服务器用 `secrets.SystemRandom` 产生；模拟器改用 `random.Random(seed)` 以便复现。

## 断线与刷新

加入时服务器发一个 token，浏览器存在 `localStorage`。刷新页面后前端用 token
重新 `hello`，服务器按 token 找回玩家并把私密状态重新发过去。

`ROUND_RESULT` 阶段只等在线玩家点「继续」，掉线的人不会卡住整局；
`ACTION_SELECTION` 阶段房主可以「强制推进」，未锁定的玩家按本轮不出牌处理。

## 前端渲染冒烟测试

`tests/test_ui_smoke.py` 会打一整局、录下每个阶段真实的 public/private payload，
然后用 node 把 `static/app.js` 加载起来（配一套最小 DOM 桩）逐屏渲染一遍。

存在的理由：前端渲染里任何一处 `ReferenceError` 都会让 `render()` 提前退出，
界面就**停在上一屏不动**，而 Python 那边的测试一个都抓不到。
真踩过一次——终局画面调了一个已经被删掉的函数，玩家永远卡在"结算中"。

同时 `render()` 本身也加了兜底：先切屏再填内容，出错就报 toast 并继续，
不会再整个冻住。没装 node 的环境会跳过这两个用例。

## 思考型 AI（ai.py）

`SmartAgent` 只接受两样输入：`game.public_state()` 和它自己的
`game.private_state(pid)`——和浏览器里那个玩家拿到的 JSON 一模一样，
所以偷看别人的金钱或手牌在结构上就做不到。

它从公开信息里推断隐藏的金钱：

* **财富广播完全没响 = 本轮全场无人贪污**，这是确定信息，所有人的钱都没变
* 被广播点名 = 他就是本轮贪污榜首，金额落在那个档位区间里
* 某人政绩没涨 = 他本轮没打 WORK（政绩是公开数据）
* "四处打点"晋升 = 他的钱至少够门槛
* 被举报查实 = 他本轮的赃款被没收了

它还会随对局自适应：从「观测到的被查实次数 ÷ 估计的贪污次数」反推这桌人举报得有多凶，
据此决定自己敢不敢贪。

有人下一步就夺冠时它会**把举报和攻击一起压在那个人身上**，
手上一张干扰牌都没有的话还会花钱重抽去拦他——
这种时候分散火力谁也拦不住，而他赢了桌上每个人都输。

`ATTACK` 的估值是 mode-aware 的：它会按当前 `ATTACK_MODE` 真实算出"打掉多少 / 我拿到多少"，
把**进我账的那部分**全额计入，把**对方的损失**乘上 `1/(对手数)` 的稀释系数
（我一个人付出整个回合，好处却是全桌分）。负和模式下它还会按"我最近被攻击的频率"
折算互攻两败俱伤的风险。

结算结果里额外给出了结构化的公开事实（`player_facts` / `wealth_top_ids` /
`wealth_tier`），内容和公开通报文字完全等价，只是不用让 AI 去解析中文句子。
`test_game.py::TestPrivacy` 有专门的用例保证这里没混进任何私密字段。

```bash
python3 analysis.py --agents smart --section choices   # AI 到底会选哪张牌
python3 analysis.py --agents smart --section leader    # 高水平对局的平衡性
```
